## Reply Quality Findings

  - 未询问用户是否确认需要如此宽松的权限

  - 应该：查到即行动，而非每一小步都播报

- **长任务缺少进度预期** (Cases 4-8)
  - AI 新闻搜索 + 语音播报是跨会话长任务
  - 没有说明"预计需要 X 分钟"或"会分几步完成"

- **MiniMax TTS 脚本依赖 ffmpeg/ffprobe 但缺少友好提示** (Case 5)
  - 报错信息可能让用户误以为 token 丢失

### Delegation/Workflow Gaps

- **跨会话任务状态丢失** (Cases 4→5→6→7→8)

  - 中间用户追进度时，助手没有明确"当前任务状态"
  - 建议：长任务应有持久化的 task-state 或进度追踪

## Improvement Suggestions

1. **配置变更前确认安全意图**
   - 修改 elevated、allowFrom 等安全敏感配置时，先问用户确认
   - 提供选项："全量放开" vs "仅允许 X 用户/频道"

2. **长任务主动报进度**
   - 预计耗时 >2 分钟的任务，开始时说明"预计需要 X 分钟，分 N 步"
   - 中途遇到延迟（如 GitHub 抓取卡顿），主动报告"卡在 X，重试中"

3. **减少不必要的中间状态播报**
   - 查 token、查配置这类内部步骤，找到即行动
   - 只在关键节点播报："找到了"、"成功了"、"失败了"

4. **跨会话任务状态追踪**
   - 对于长任务，应在 task-state.json 中记录当前阶段
   - 用户问"进展如何"时，能快速回显"当前在 X 阶段，已用时 Y 分钟"

5. **轻任务也走八爪鱼 route**
   - 安装、配置类任务虽简单，但涉及本机工具，应先 route 判断
   - 保持与八爪鱼原则一致性
