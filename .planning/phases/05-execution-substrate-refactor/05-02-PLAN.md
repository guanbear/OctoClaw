## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| validated policy decision -> TS dispatch orchestrator | Route authority must be consumed once and not re-judged by a second live-path authority |
| TS workflow state -> native task/flow substrate | Runtime-core owns lifecycle intent while native task/flow remains execution truth |
| lifecycle truth -> status/read models | Projection and telemetry surfaces must not overwrite or reconstruct execution truth |

| T-05-02-01 | T | `extensions/octoclaw-runtime/index.js` | mitigate | Remove `dispatch_task.py`, `octoclaw_spawn.py`, and `task-state-update.py` from formal live execution and bind live routes to TS orchestration seams only. |
| T-05-02-02 | E | spawn and runner materialization | mitigate | Require validated route decisions and TS-native materialization; fail closed when native substrate materialization cannot proceed. |
| T-05-02-03 | I | lifecycle/status separation | mitigate | Emit lifecycle truth from runtime-core and native substrate records while keeping projection, artifact, and telemetry payloads read-only derivatives. |
| T-05-02-04 | D | delegated route fallback | mitigate | Add acceptance proving delegated routes either materialize natively or fail with TS-owned errors, never Python wrapper or shell preflight failures. |
</threat_model>
